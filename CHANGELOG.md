# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added
- `package.json` + `scripts/diagrams/tool_versions.py`: `@mermaid-js/mermaid-cli` and `@marp-team/marp-cli` are now pinned to exact versions. Unpinned, `npx -y <pkg>` resolved whatever was newest — mermaid-cli had reached 12.0.0 and marp-cli 4.2.3, so the same deck could render differently tomorrow and the golden SVG fixtures would fail for reasons nobody changed. A test fails if `package.json` and the Python pin disagree; `MARP_CLI_SPEC` / `MERMAID_CLI_SPEC` override at runtime. The pin ships inside `marp-diagram-creator/vendor/`, so standalone installs are pinned too.
- `tests/test_marp_lint.py`: 138 direct unit tests for `marp-lint.py` — every `lint_*` check, its near-miss cases, and the CLI exit-code contract. No test had referenced any of its check functions, so a false positive would make an agent "fix" a correct slide and a false negative would ship a broken one.
- `tests/test_tool_versions.py`: 31 tests covering the pin, the `npx` argv shape, the absence of `shell=True`, and the npm-cache location.
- `scripts/sync-skill-vendor.py` + `skills/marp-diagram-creator/vendor/`: the `marp-diagram-creator` skill now ships the diagram runtime (renderer, validator, 17 templates, 6 theme palettes — 174 KB, 33 files). `scripts/diagrams/` stays the development source; the vendored copy is generated and `--check` fails on drift. Repository-only tooling (`check-*.py`, `sync-*.py`, `theme_classes.py`, the test suite) is deliberately excluded — it reads `README.md` and `themes/*.css` and cannot work outside a checkout.
- `skills/marp-diagram-creator/scripts/print-engine-path.py`: prints the absolute path to the vendored engine, so a skill installed at an unknown location can still resolve it. Replaces hard-coded `scripts/diagrams/...` paths, which only existed inside a checkout.
- `scripts/diagrams/theme_classes.py`: single source of truth for class semantics (`LIST_UNSUITABLE_CLASSES`, `TITLE_EXEMPT_CLASSES`, `LIST_EXEMPT_CLASSES`, and the class → layout-profile map), parsed from `themes/*.css`. `marp-lint.py` previously carried three hard-coded, mutually inconsistent class sets.
- `scripts/diagrams/sync-theme-classes.py` + generated `skills/marp-slide-creator/scripts/theme-classes.json`: ships the semantics to the linter, which is copied standalone into agent directories and cannot import from `scripts/`. `--check` is the CI gate. A missing manifest now fails loudly instead of silently disabling the class-based checks.
- `scripts/diagrams/check-class-docs.py`: verifies the README class reference against the CSS in both directions — an implemented class must be documented, and a class documented as universal must exist in every theme. `--allow-unlisted` downgrades to a warning while documenting incrementally.
- Fork-drift guard (`tests/test_theme_fork_drift.py`): compares `azure-clarity` and `crimson-clarity` with colours and token names normalised, so any *structural* difference fails. `warm-sunnyday` is checked for component parity only, since its radii and step badges differ by design.
- Sample-deck guard (`tests/test_sample_decks.py`): runs the real `marp-lint.py --structural-only` and `post-edit-check.py --lang ja` over every `slides/sample-slide/*.md`, checks each deck's frontmatter theme matches its filename, and verifies no deck uses a class its own theme does not implement.
- `scripts/diagrams/check-templates.py`: renders and canvas-validates every on-disk template at each layout it claims to support, and fails when a template is missing from that list (so a new template cannot escape validation). Replaces the old CI loop that only echoed Mermaid filenames and checked draw.io at one layout. `--skip-mermaid` for an offline run, `--engine` to narrow. Verified matrix is published in the README and `template-catalog.md`.
- `take-screenshots.py --list-themes`: prints the screenshot registry and validates every hard-coded slide index against the real sample decks (no browser or Marp CLI needed). Exits non-zero on drift, and runs in CI.
- `warm-sunnyday` and `slate-minimal` screenshot sets: all 13 previously-unregenerable README images are now produced by `take-screenshots.py`.
- Font manifest guard: `tests/test_fonts_manifest.py` fails on a `@font-face` pointing at a missing file, on bundled-but-unreferenced fonts, and on a bundled font missing from `NOTICE.md`.
- JSON diagram types `bar`, `line` (multi-series `categories`+`series`), and `stacked-bar` with shared cartesian frame (nice-tick axes, themed legends): `templates/charts/sales-bar.json`, `quarterly-line.json`, `channel-stacked-bar.json`.
- Theme token pipeline: `scripts/diagrams/sync-tokens-from-css.py` (CSS `:root` → `theme-styles/*.json`, `--check` for CI drift), `design_tokens.py` (incl. luminance-based `best_text_on`), `svg_theme_postprocessor.py`, `svg_filters.py`.
- Golden regression fixtures: `scripts/diagrams/tests/fixtures/diagram-golden/` (6 themes × 3 engines) with `regenerate-golden.py` and `test_golden.py`.
- `sales-funnel.json` template; CSS-native `grid-quadrant axes` and `steps arrows` patterns with `prism-edge` samples.
- Regression suites (806 tests): token sync, contrast, connector geometry, golden, funnel/pyramid/radial/pie, postprocessor, text quality, visual balance, aspect control, key-message theme contract, CLI exit-code/encoding contract, template-gate completeness, font manifest, screenshot registry integrity, theme class semantics, README/class-doc parity, theme fork drift, sample-deck compliance, vendored-engine drift and standalone execution, `marp-lint.py` check functions, pinned Node tool versions.
- Aspect-ratio control: new `scripts/diagrams/svg_aspect.py` (`parse_aspect` accepting `2.4`/`16:9`, `%% aspect:` Mermaid directive extraction, `pad_viewbox` centering padding within `VALIDATOR_LIMITS`), JSON `"aspect"` field (derives `height` from `width`, mutually exclusive with `height`), and `render-slide-diagram.py --aspect 2.4|16:9` for all three engines. Validator aspect warnings now include an actionable re-render hint with the suggested ratio.
- Contract tests: `tests/test_theme_keymessage.py` (static + Playwright computed-style checks that the key-message quote inherits/differs from the subtitle in all 6 themes) and `tests/test_cli_contract.py` (non-zero exit on validation failure, `--no-validate` escape hatch, UTF-8 output under a cp932 console).

### Changed
- draw.io routing (`diagram_routing.py`, renderer, validator share one path): perpendicular port snapping, container→edge→node z-order, arrowheads on path ends, cylinder port spans.
- Mermaid postprocessing: edges/arrowheads in theme line color, gray-shadow removal, 1.5px+ strokes; pie palette order, 2.5px separators; title 22 / label 15 typography.
- `theme-styles/*.json` schema (colors/shapes/effects/typography/signature) synced from `themes/*.css`; Nebula dark-fill contrast fix.
- `marp-diagram-creator` skill: engine decision tree + quick ref; template catalog updated; `aspect`/`--aspect` documented in `SKILL.md` and `diagram-patterns.md` §1; `ADD_NEW_DIAGRAM_TYPE.md` notes that `aspect` is inherited centrally.
- `templates/mermaid/flowchart-linear.mmd` pins `%% aspect: 2.4` (recommended full-slide ratio, embeds at 1050x437); the 6 golden flowchart fixtures were regenerated accordingly and now validate with 0 warnings.

### Fixed
- `marp-lint.py` classified a file as a diagram and as an icon at the same time. `lint_oversized_icons` skipped only the hard-coded pair `("diagram", "chart")` while `lint_diagram_embedding` matched nine keywords, so `assets/flow.svg` was a diagram to one and an icon to the other. A correct `width:500px` two-column embed produced a false `OVERSIZED_ICON` **ERROR**. Both checks now share one predicate.
- `marp-lint.py` numbered slides by their position in the split, so a blank slide between two `---` separators shifted every later number (1, 3 instead of 1, 2) and the reported slide no longer matched the section index Marp and the DOM extractor use for the same deck.
- `take-screenshots.py` and `render-slide-diagram.py` built a shell command string with `shell=True`, re-parsing deck paths and providing an unnecessary injection surface. Both now pass an argv list.
- `marp-diagnostics.py` hard-coded its npm cache to `C:\tmp\npm-cache`, creating a directory at the Windows drive root and failing outright for a user without write access there. It now uses `NPM_CONFIG_CACHE`, then `%LOCALAPPDATA%`, then the platform temp dir.
- `marp-diagram-creator` was structurally broken outside this repository. It was 3 files / 20 KB of prose pointing at `scripts/diagrams/render-slide-diagram.py`, which lives *outside* the skill, so every documented command resolved to a non-existent path once the skill was copied to `~/.claude/skills/` or a colleague's machine. The engine is now vendored into the skill and verified to render identically with no repository present.
- The nine `slide-expert-*` skills all carried a diagram warning pointing at `scripts/diagrams/render-slide-diagram.py`; they now point at the `marp-diagram-creator` skill that owns the engine.
- `cover-nebula` and `glass-card-layout` were missing from `marp-lint.py`'s title-exempt set, so a Nebula cover titled "概要" produced a false `WEAK_TITLE` warning — on the exact pattern the `marp-diagram-creator` skill's quick start demonstrates. `split-glass` was treated as a single column for bullet limits while being a 2-column layout for diagram widths, so 5–6 bullets on a `split-glass` slide were warned against a limit of 4. Both now derive from one class manifest generated from the CSS.
- `marp-lint.py` exits with a clear message and a repair command when `theme-classes.json` is missing, rather than failing with a `KeyError` on the class sets.
- `marp-lint.py`'s `CENTERED_LIST` and `DIAGRAM_ON_CENTERED_LAYOUT` checks now key on layout *purpose* rather than a CSS property, because several themes deliberately left-align their covers (`slate-minimal`, `cover-diagonal`, nebula's `key-message`) while still being single-message layouts.
- Theme CSS gaps that broke the documented "unified class system" claim: `v-middle` was missing from `nebula-glass` and `slate-minimal`; `pagination-left` from `nebula-glass`; `align-left/center/right` from `nebula-glass` and `slate-minimal`; `text-accent`, `text-blue`, `text-green`, `text-orange`, `text-red` and `text-sub` from `nebula-glass`. All implemented.
- `nebula-glass` had no `cover` class at all, so a deck could not switch to it without also rewriting its class directives. `cover` is now an alias of `cover-nebula` (identical chrome, typography and gradient). Note: existing decks that used a plain `cover` on `nebula-glass` will now receive the `cover-nebula` design (header/footer/pagination hidden, 76px title); rename to another class if the old unstyled look was intended.
- `azure-clarity` was missing the `.callout.blue h4` rule that `crimson-clarity` had, so a blue callout heading rendered in the body colour there. Both themes now declare `--*-info` / `--*-info-pale` tokens and use them; `crimson-clarity` and `warm-sunnyday` no longer hard-code the blue callout colours, so editing `:root` actually retheme them.
- `sync-tokens-from-css.py --check` was only comparing the `signature` block, so a CSS color change that left the signature untouched (e.g. `--ac-text`) passed CI while `theme-styles/*.json` went stale. The check now runs the write path against a deep copy and reports drift for colors, shapes, effects, signature and the derived draw.io styles, naming the field and the exact command to repair it. Regression test: `test_sync_check_detects_non_signature_color_drift`.
- Mermaid templates `sequence-api.mmd`, `flowchart-col2.mmd` and `state-machine.mmd` exceeded the 470 px canvas height at every layout and could not be rendered at all without hand-editing. All three now fit: `flowchart-col2` is 3 levels deep, `sequence-api` merges the DB round-trip into one message, and `state-machine` is laid out left-to-right and padded to `%% aspect: 2.4`.
- CI no longer skips silently: `playwright` + Chromium are installed before the test run, so the browser-backed theme contract tests in `test_theme_keymessage.py` actually execute instead of skipping.
- CI trigger paths widened to `themes/`, `scripts/`, `skills/`, `slides/`, `assets/` and the workflow itself. The previous list omitted `scripts/sync-skills.py` and `scripts/take-screenshots.py` even though both have test suites.
- `split-glass` and `glass-card-layout` were documented as asymmetric (710 px) in the README, but `nebula-glass.css` defines `split-glass` as a 50/50 `1fr 1fr` grid and `glass-card-layout` as a single centred column. A diagram embedded at the documented 680 px would fail `DIAGRAM_OVERFLOW_WIDTH` (520 px limit). Both the README and `theme-expert-nebula-glass` are corrected, and `layout_spec.py` records why they are budgeted as `col2`.
- `marp-lint.py` computed the bullet-count threshold from its own hard-coded class set, which disagreed with the diagram-width class set in the same file and omitted `split-glass` / `glass-card-layout`. A `split-glass` slide with 5-6 bullets was warned against a limit of 4. Both checks now derive from one `_slide_layout_key()`, so they cannot drift.
- `marp-lint.py` had a dead `MAX_RECOMMENDED_BULLETS = 5` constant that nothing read, and a `DENSE_CONTENT` message hard-coding "200-350" while the real limit was 400. Both now derive from the actual constants.
- `take-screenshots.py` died on its own progress output under a cp932 console (`UnicodeEncodeError` on the first emoji). It now forces UTF-8 on stdout/stderr like the other scripts, and reports an unknown theme name instead of a `KeyError`.
- Windows console encoding: `render-slide-diagram.py`, `validate-slide-diagram.py`, `marp-lint.py`, `marp-diagnostics.py`, and `take-screenshots.py` force UTF-8 on stdout/stderr, so Japanese text and file names no longer require manually setting `PYTHONIOENCODING=utf-8` (cp932 consoles/pipes).
- CLI exit codes: `render-slide-diagram.py` now exits non-zero when layout validation fails (it previously printed `[WARN]` and still reported `[SUCCESS]` with exit 0, letting broken geometry through automation); `regenerate-golden.py` inherits this strictness because it already propagates render return codes.
- Validator overlap epsilon: `_rects_overlap` in `validate-slide-diagram.py` now uses `OVERLAP_EPSILON = 0.05` so sub-pixel node borders no longer false-positive as overlap.
- Pyramid renderer no longer drops level descriptions that outgrow the trapezoid — `svg_diagram_renderer.py::_pyramid` pads to 16px and falls back to outside placement (`outside_description()`).
- `key-message` quote text: `section.key-message blockquote p` now inherits size/color in all 6 themes (`azure-clarity`, `crimson-clarity`, `warm-sunnyday`, `slate-minimal` gained the rule alongside the earlier `prism-edge` fix; `nebula-glass` already specified its own explicit size).
- `warm-sunnyday` used the `--ac-*` prefix, colliding with `azure-clarity` when both themes load. All 141 variables are renamed to `--ws-*` (the prefix `theme-creator` already documented); `sync-tokens-from-css.py`, the fork-drift tests and the README token table follow. Note: existing decks overriding `--ac-*` on `warm-sunnyday` must rename to `--ws-*`. Its cover also carried azure-blue leftovers (`rgba(27,79,114,...)` shadow, `rgba(44,123,229,...)` meta pill), now `rgba(110,59,59,...)` / `rgba(255,140,66,...)`.
- `slate-minimal` `toc-focus ol` had `margin: 12x 0 0 0` (invalid unit, declaration dropped). Now `12px`.
- `.gitignore` negation `!.github/workflows/` never un-ignored the workflow file itself (now `!.github/workflows/**`); `node_modules/` and `.dist/` are ignored.
- Renderer/validator no longer crash on malformed numbers: `pageWidth/Height`, `mxGeometry`, `startSize`, `fontSize`, SVG `viewBox` and path data go through `_safe_float`/`_safe_int` (invalid `viewBox` is reported as an error). `ET.parse` also catches `OSError`.
- Every `subprocess.run` to Node/Marp tooling now sets `timeout=300`, `encoding="utf-8"`, `errors="replace"` and catches `TimeoutExpired`/`OSError` (`render_mermaid`, validator call, `build_html`, `check-templates.py`, `regenerate-golden.py`); all Playwright `browser` uses in `take-screenshots.py` close in `try/finally`.
- Timeline markers used `translateY(calc(0.5lh - 50%))`; the `lh` unit is unsupported in older Chrome/Marp, so all five themes now use `0.5em` like `slate-minimal`.
- `nebula-glass` Safari/Firefox gaps: `-webkit-backdrop-filter` alongside every `backdrop-filter`, and standard `background-clip: text` alongside the three `-webkit-background-clip: text` uses (mirrors `prism-edge`).
- Selector scoping: `slate-minimal`'s `.callout/.badge/.text-*/.bg-*` and `nebula-glass`'s `.gradient-text/.glow-*` were global and leaked across slides; all are now `section`-scoped like the other themes. `theme-classes.json` regenerated.
- Sample decks no longer depend on the network: `nebula-glass-sample.md` used `https://placehold.co/...` (now local `sample_image.jpg`); the dead `dummyimage.com` comment in `slate-minimal-sample.md` is removed and its image has a real alt/size.
- Badge/text contrast (all measured, WCAG AA 4.5:1): `azure-clarity` blue badge now on `primary-dark` (4.14 -> 6.10), green/red badges on `#1E8449`/`#CB4335` (white 4.72/4.78); `crimson-clarity` green/red likewise, orange badges use dark body text (7.78/8.35); `warm-sunnyday` badges are outline style with dark text on white (pastel fills pass with neither white nor dark text); `warm-sunnyday --ws-text-sub` darkened `#8E7C75` -> `#6F5F59` (3.91 -> 5.98); `slate-minimal` semantics re-stepped to distinct passing grays (`success #475569`, `warning #64748B`, `danger #1E293B`). `theme-styles/*.json` resynced.
- CI hardening (`diagram-checks.yml`): `permissions: contents:read`, `concurrency` cancel-in-progress, per-job `timeout-minutes: 30`, pip cache, JUnit artifact upload on failure, and a `windows-checks` job (no browser/Node — covers the cp932 console and `npx.cmd` shape the ubuntu runner cannot).

### Removed
- Unreferenced bundled fonts: `Carlito` (4 faces) and `Liberation Mono` (4 faces), 3.9 MB that no theme ever loaded. `assets/fonts/` drops from 27 to 19 files (26.1 MB -> 22.3 MB); `NOTICE.md` now maps every remaining file to the theme that uses it and states that `azure-clarity` / `crimson-clarity` bundle nothing.
- Orphan screenshots: `azure-clarity-cols.png`, `azure-clarity-step.png`, `crimson-clarity-cols.png`, `crimson-clarity-step.png` were referenced by the README but not produced by `take-screenshots.py` (it wrote `cols2` / `steps`). The README now uses the generated names and all 58 registry images are reproducible.
- Orphan docs: `docs/diagram-engine-selection-guide.md`, `docs/diagram-quality-baseline.md`, `docs/plans/`, `docs/diagram-golden/README.md`.
- Superseded templates: JSON `timeline` type, `comparison-matrix.drawio`, `timelines/product-roadmap.json` (CSS Native replaces them); `slides/diagram-demo/` generated artifacts.

## [0.1.0] - 2026-05-15

### Added
- **Initial Public Release**: A curated collection of AI-optimized Marp themes.
- **5 Professional Themes**:
  - `azure-clarity`: Clean corporate blue.
  - `crimson-clarity`: High-impact corporate red.
  - `prism-edge`: Modern bold indigo-cyan.
  - `nebula-glass`: Dark glassmorphism tech-premium.
  - `warm-sunnyday`: Friendly warm orange.
- **AI Agent Integration**:
  - Custom "Skills" for Claude Code, Windsurf, Cursor, Kiro, and GitHub Copilot.
  - `scripts/sync-skills.py`: Easy setup script for syncing skills to local AI agents.
- **Unified Component System**: Ready-to-use classes for covers, grids, timelines, callouts, and multi-column layouts.
- **Toolkit**: Pre-render linter (`marp-lint.py`) and layout diagnostics helper (`marp-diagnostics.py`).
- **Sample Decks**: Complete demonstration slides for each theme.
